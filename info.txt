Should Crashed be in Ship?
Short answer: no, not in your current design

You asked:
g.Ship.Crashed?

That would mean:
Ship owns its state
But in your game, crash is:
👉 a game rule, not a ship property

Entities don’t decide game rules — the Game does.
Ship = data + movement
Game = rules (collision, win, lose)

Import/Export

Rule: capital letter = exported (public)
type Ship struct {   // ✅ exported
    X float64       // ✅ exported
    vx float64      // ❌ private
}
X → accessible from other packages
vx → only inside same package

All your files use:
package main

That means:
everything is in the same package
you can access everything regardless of capitalization

Only when you do:
package physics

Then:
ApplyGravity() → usable outside
applyGravity() → NOT usable

same folder + package main → everything shared
different package → capital letters matter

SIN/COS

sin/cos = “walk around a circle using an angle”

Formula for the position of the mineral in the edge of planets
x=Cx​+rCos(θ),y=Cy​+rSin(θ): 
Cx, Cy = planet center, 
r = planet radius (distance from center), 
θ = angle (where around the circle)

spreads minerals evenly around the circle
angle := float64(index) * (2 * math.Pi / float64(p.Minerals))

COS
cos(angle) = horizontal movement (left/right)
x := p.X + p.Radius * math.Cos(angle)

SIN
sin(angle) = vertical movement (up/down)
y := p.Y + p.Radius * math.Sin(angle)

Generate minerals randomly (with spacing)
We randomly generate points inside a circle:
x=Cx​+rcos(θ)	​
y=Cy​+rsin(θ)

But with random radius + angle.

RETURNS (UPDATE VS DRAW)

Why return nil in Update() but just return in Draw()?

Update()
func (g *Game) Update() error
Must return an error
nil = “no error”
So:
return nil

Means:
“Game is fine, keep running”

Draw()
func (g *Game) Draw(screen *ebiten.Image)
Returns nothing

So:
return

Means:
“Stop drawing more stuff this frame”

Rule
- functions with return type → must return value
- void functions → just return (optional)

------------------------------------------
IMAGE VS DRAWING

Image vs drawing a circle (important concept)

Draw
screen.Set(x, y, color)
sets pixel directly
❌ no blending
❌ slow (per pixel every frame)
❌ no transparency

Image
screen.DrawImage(img, op)
draws precomputed pixels
✅ supports alpha blending
✅ GPU accelerated
✅ reusable
✅ can scale/rotate/tint

Mental model:
Set() = manual pixel painting
DrawImage() = rendering a sprite
👉 Real games = almost always use images

POINTERS

Example:
func drawShip(screen *ebiten.Image, game *Game)

The * means:
pointer to Game
NOT a copy.

Without *
func drawShip(screen *ebiten.Image, game Game)

This copies the ENTIRE Game struct every function call.

Your Game contains:
planets slice
ship
booleans
level
images

That’s expensive.

What a pointer actually means
game *Game

means:
“use the original Game object in memory”

instead of:
“make a duplicate copy”

FIND THE SQUARE AREA OF AN OBJECT'S center

for i := -int(p.Radius); i < int(p.Radius); i++ {
	for j := -int(p.Radius); j < int(p.Radius); j++ {
    }
}

This is scanning a square area around the planet center.

Suppose:
p.Radius = 30

Then:
i goes from -30 to +29
j goes from -30 to +29

Planet's center: (0,0)

Loop checks every pixel around center:
(-30,-30) -------- (30,-30)
     |                 |
     |      center     |
     |       0,0       |
(-30,30) --------- (30,30)

Outer loop moves horizontally. (for i := ...)
Inner loop moves vertically. (for j := ...)

Together, every combination of (i, j) gets checked.
(-30,-30)
(-30,-29)
(-30,-28)
...
(0,0)
...
(29,29)

So you're checking every pixel inside a square.

CREATE A CIRCLE 
if i*i + j*j <= radius*radius

This is the circle equation:
x2 + y2 ≤ r2

Meaning:
points inside radius are drawn
points outside are ignored

So:
loop scans square
equation cuts circle out of square

SPEED 

VX = horizontal movement
VY = vertical movement
speed = SQRT(VX2 + VY2)
velocity is a vector: movement in X and Y combine diagonally > length of the velocity vector

ROTATION 

"What angle is this velocity vector pointing?"
Velocity: VX = 1, VY = 0 - moving right - Angle = 0 radians
Velocity: VX = 0, VY = -1 - moving up - Angle = -PI/2
Atan2(y, x) returns the angle of a vector
rotation=atan2(VY,VX) + PI / 2
